## [OpenAI 发布 GPT-6.1 Sol：接近 Astra 的智能，只要五分之一的价格](https://techcrunch.com/2026/09/29/openai-launches-gpt-6-1-sol-says-it-nearly-matches-gpt-6-astra-and-costs-less/) ⭐️ 9.0/10

OpenAI 发布了 GPT-6.1 Sol，这是 GPT-6 Sol 的升级版。官方称其在 agentic coding、computer use 和专业工作上的智能几乎追平 GPT-6 Astra，而标准输入输出 token 价格仅为 Astra 的五分之一。相比 GPT-6 Sol，它在代码编写与调试、文档理解以及多步骤业务流程执行上也有显著提升。 这很重要，因为它把中端模型和旗舰模型之间的价格鸿沟直接抹平了——如果“接近追平”的说法站得住脚，大多数团队就没必要再为 Sol 能干的活去付 Astra 的钱。真正的赢家是那些大规模部署 agent 的人，因为 token 成本才是 agentic 产品背后沉默的杀手。 最扎眼的数字是：标准输入输出 token 价格只有 Astra 的五分之一，这种降幅足以一夜之间改变产品的单位经济模型。但官方措辞限定在 agentic coding、computer use 和专业工作场景，并不是笼统地说“全面追平 Astra”——等 benchmark 出来时，这一点值得记在心里。

rss · TechCrunch AI · 9月29日 17:15

**背景**: OpenAI 的 GPT-6 家族分三档：Luna、Sol、Astra，能力从低到高排列。Astra 于 2026 年 9 月 4 日向公众发布，Sol 和 Luna 则在 9 月 22 日跟进。Astra 是旗舰，在 computer use、browsing、软件工程、cybersecurity、科学和专业工作上都是 state-of-the-art；Sol 则是用类似方法训练出来的便宜干活主力。可以把它想成汽车产品线：Astra 是满配旗舰，Sol 是中配版本，而 GPT-6.1 Sol 就是今年的改款——从旗舰那里借了足够多的东西，让你很难拒绝升级。

## [OpenAI 发布 GPT 6.1 Sol：接近 Astra 的智能，价格只要五分之一](https://openai.com/index/introducing-gpt-6-1-sol/) ⭐️ 8.0/10

OpenAI 发布了 GPT 6.1 Sol，定位在旗舰模型 GPT-6 Astra 之下，定价为每百万 input tokens $2、每百万 cached input tokens $0.10、每百万 output tokens $10——大约是 Astra 标准 API 价格的五分之一。它已通过 API 以 gpt-6.1-sol 的名称开放，并已在 Devin Desktop 和 Devin CLI 上线，但尚未进入 ChatGPT。 这是件大事，因为真正的头条不是模型本身，而是价格战。cached input 每百万 tokens 只要 $0.10，比 GPT-6 Sol 的缓存价格便宜 50%，这意味着重度 Codex 用户每一美元能跑出多得多的量。OpenAI 显然是在回应 Anthropic Opus 5.5 的势头，靠成本而非纯 benchmark 领先来竞争，这一转向很能说明行业的走向。 最巧妙的地方在于缓存经济学：OpenAI 会自动缓存 1024 tokens 以上的 prompt，但无论缓存前缀是否被再次读取，每次缓存写入都会计费——这是个微妙的坑，如果你的 prompt 频繁变动就会被咬到。在 Devin 的排行榜上，GPT 6.1 Sol 在 low effort 下以每任务 $0.21 的成本拿到 58.1% 的分数，相比同设置下 GPT-6 Sol 的 50.5% 有明显提升，成为每任务 $0.30 以下得分最高的模型。

hackernews · OpenAI Blog · 9月29日 17:06 · [社区讨论](https://news.ycombinator.com/item?id=49896586)

**背景**: 把 OpenAI 的 GPT-6 系列想象成汽车配置阶梯：Astra 是顶配旗舰，Sol 是中配，Luna 再低一档。问题在于，之前的 Sol 6 和 Luna 显然在开发者那里翻了车——一位 Hacker News 评论者说 Sol 6 相比 Sol 5.6 是巨大退步，以至于他彻底转投 Anthropic 的 Opus 5.5。所以 GPT 6.1 Sol 是 OpenAI 试图把开发者拉回来的尝试，靠的不是地球上最聪明的模型，而是足够好、且大规模运行时便宜得多。

Hugging Face 的一篇新博客文章为 MCP agent 引入了 source-aware verification，认为仅检查一个 claim 是否为真还不够——还必须检查它来自的 source 是否可信。该方法建立在 ProvenanceGuard 论文之上，将 agent 的回答拆解为单个 claim，保留原始 tool 输出中的稳定 MCP tool ID 和 source ID，并将每个 claim 路由到特定 source 的证据。 这是一个真正重要、值得填补的空白。目前大多数 AI agent 的 fact-checking pipeline 只问“这个 claim 是否为真？”，却从不问“它来自哪里，那个地方可信吗？”当 agent 从几十个 MCP tool 拉取信息时——有些权威，有些是抓取的垃圾——混淆 source 正是产生“自信地答错”的根源。这项工作把 provenance 提升为一等公民，方向完全正确。 巧妙之处在于 ProvenanceGuard 不只是验证 claim——它还能检测 cross-source conflation，也就是捕捉 agent 把来自两个不同 tool 的证据混成一句误导性陈述的情况。它报告在 260 条 source-eligible claim 上取得 held-out block F1 0.802、source accuracy 0.858，成绩扎实但并非完美——大约每七个 source 归属中仍有一个出错。

rss · Hugging Face Blog · 9月29日 13:07

**背景**: MCP（Model Context Protocol）是 Anthropic 于 2024 年 11 月推出的开放标准，让 LLM 以标准化方式接入外部 tool 和数据源。可以把它理解为 AI agent 的通用适配器——不必为每个 tool 定制接线，MCP 给它们一个统一插头。但一旦 agent 同时从多个 tool 拉取信息，新问题就出现了：它可能从一个可靠 source 抓到一个事实，又从另一个不靠谱的 source 抓到矛盾的事实，然后毫无察觉地把两者混在一起。Source-aware verification 正是试图通过追踪每条信息的来源来解决这个问题。

## [两个新的 Attention 技巧大幅削减长上下文计算量，但别急着叫它无损](https://www.reddit.com/r/MachineLearning/comments/1wt1gbk/cowindow_and_massalloc_attention_collective/) ⭐️ 7.0/10

两篇新预印本提出了 CoWindow Attention \(CoWA\) 和 MassAlloc Attention \(MALA\)，这是两种互补的方法，用于削减长上下文 attention 中的冗余计算。在 8 张 H100 GPU、128K tokens、TP=8 的设置下，CoWA 报告相对 FullAttn 的 attention 算子加速为 forward 7.4x、backward 8.6x、decode 3.0x，MALA 则分别为 2.2x、3.0x、1.6x。 长上下文推理目前被 attention 的二次复杂度卡住，所以任何真实的算子级加速都值得关注——但作者自己承认这并不等同于对 dense attention 的无损等价，而且这些是算子数字，不是端到端模型加速。这种坦诚值得赞赏，但也意味着你应该把那些醒目的倍数当作上限，而不是承诺。 CoWA 通过互补窗口把远端上下文分散到各个 KV head 上，同时共享 local 和 prefix-sink 窗口，因此每个 head 稀疏地 attend，但并集覆盖完整的 causal history——关键在于它不需要学习 router 或 indexer。MALA 保留完整的 causal QK scoring，但利用 attention 自身的 softmax 统计量来决定是否对某个 tile 执行 post-score 计算，并在训练和推理中使用统一的 tolerance。

reddit · r/MachineLearning · /u/BitExternal4608 · 9月29日 05:16

**背景**: Attention 是 Transformer 中让每个 token 查看其他 token 的机制，其成本随序列长度二次增长——上下文翻倍，计算量翻四倍。KV cache 通过在生成时避免重复计算来缓解问题，但并没有解决根本的扩展性问题，这正是长上下文模型训练和推理如此昂贵的原因。这两篇论文攻击的是这种冗余的不同部分：CoWA 通过分配每个 head 能看到的位置，MALA 则通过跳过 attention score 计算之后的工作。
