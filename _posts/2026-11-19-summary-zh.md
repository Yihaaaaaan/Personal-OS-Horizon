## [AI 自己重写大脑：无需梯度，无需训练](https://arxiv.org/abs/2611.21885) ⭐️ 9.0/10

一个 27B 的开源语言模型现在能够诊断自己的失败，并直接重写自己的权重，在未见过的题目上把准确率提升 6.6 个百分点，全程无需梯度、无需训练，这个过程被称为 self-rewriting。 这很重要，因为它打破了训练与推理之间的墙：模型成为自己的优化器，把提升直接写进权重，且每次回答零额外成本。如果它能扩展，这就是迈向递归自我改进的切实一步——也意味着开源模型无需更大的父模型或 prompt engineering 就能持续变强。 模型会在练习题上测试自己的编辑，只提交有效的修改，连续八次会话中准确率只升不降；它甚至能在从未读取原始权重的情况下，把一个几乎什么都解不出的损坏副本修复到原准确率的 80% 以上。这种能力随规模涌现：同一模型家族中，较小的模型要么改不动，要么把自己改坏，只有最大的模型能自我提升并自我修复。

rss · arXiv AI · 11月19日 05:00

**背景**: 通常，语言模型训练一次就被冻结——想让它变好，要么再跑一次带反向传播的训练，要么靠巧妙的 prompt 和额外的推理时计算，而后者任务一结束就消失了。这篇论文问的是：如果模型能像读代码一样读取自己的权重，找出自己为什么失败，然后直接改数字呢？这就是 self-rewriting，它处在 weight-space programming 和 gradient-free optimization 的交叉点，但更进一步，让模型对自己的失败进行推理。

## [通用 AI 碾压专用机器人策略：零样本 85.6% vs 49%](https://arxiv.org/abs/2611.09892) ⭐️ 9.0/10

一篇新的 arXiv 论文提出了 Agentic Manipulation Policies \(AMPs\)，其中通用 AI 模型通过编写 Python 代码直接控制机器人操作器，在 RoboLab-120 上实现 85.6% 的零样本成功率，而领先的 VLA 策略为 49.2%，WAM 策略为 42.9%。在真实世界试验中，AMP1 框架在十二个任务和三个机器人实例的 108 次尝试中成功了 104 次，相比 VLA 和 WAM 基线将失败率降低了 20 倍和 15 倍。 这很重要，因为它挑战了主导机器人学习的整个专用策略范式——当通用模型可以即时摸索出解决方案时，为什么还要在数千次演示上训练定制的 VLA？如果这些结果站得住脚，机器人行业对海量演示数据集和任务特定微调的痴迷可能是一条昂贵的弯路。 基础的 AMP1 框架不提供任何抓取、推动或放置技能——智能体自行开发策略，例如寻找隐藏物体、将物体用作工具以及校准摄像头。在多个回合中添加持久记忆存储后，RoboDojo 双臂任务的失败率又降低了 4.6 倍，表明该智能体无需梯度更新就能从经验中学习。

rss · arXiv AI · 11月19日 05:00

**背景**: Vision-language-action 模型 \(VLAs\) 是当前机器人学习的宠儿：你在大量机器人轨迹数据上微调一个视觉语言模型，使其能将图像和指令直接映射为电机命令。World-action models \(WAMs\) 是一种更新的变体，还会预测场景将如何演变，借鉴了视频生成骨干网络。两者都是专用方法——它们需要演示和任务特定训练。AMPs 颠覆了这一模式：不训练策略，而是给前沿通用模型一个连接机器人传感器的代码接口，让它通过推理完成任务，更像程序员调试机器人，而不是神经网络 regurgitating 轨迹。

## [Perplexity 推出 Orchestrator API，要做你的 LLM 流量警察](https://www.marktechpost.com/2026/11/19/perplexity-orchestrator-api-failover-model-routing/) ⭐️ 7.0/10

Perplexity 发布了 Orchestrator API，通过单一 endpoint 接入 OpenAI、Anthropic、Google、xAI 以及 open-weight 模型，并提供同模型跨 provider 的 failover、统一计费，以及一个 preview 版的 perplexity/auto router——它根据自然语言写的 route 描述来为每个请求选择模型。 这是一个真正有用的“管道”型产品：那些受够了五个 API key、五个账单后台和凌晨三点 provider 宕机的团队，现在可以用一个 endpoint 拿到自动 failover。它不是范式转移，但正是这种不起眼的基础设施能实打实省下工程时间——同时也把 Perplexity 放到了 OpenRouter、Requesty 同一条赛道上。 最巧妙的是 auto-router：一个 decision model 读取对话内容和你的 route 描述（而不是 route 名称或 model ID），据此选择某条 route 或都不选，并回退到 default model。Perplexity 还把“同模型部署 failover”和“可选的模型选择”分开处理，这样在 provider 降级时，指定精确模型的请求依然可预测。

rss · MarkTechPost · 11月19日 17:47

**背景**: 如果你在 LLM 上做开发，大概率曾经写死过某一家 provider，然后发现 uptime 根本没有保证。LLM router 就夹在你的应用和各家 provider 之间，把每个请求发给你想要的模型，并在某个 provider 失败时换一家重试——可以把它理解成 AI 模型的负载均衡器。Perplexity 最出名的是它的答案引擎，但这个 API 是在赌开发者愿意为可靠性和模型灵活性付费，而不是死守一家厂商。
